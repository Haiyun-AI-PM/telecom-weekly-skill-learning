## V1｜逐级嵌套与数量一致性

**原输出**：`prior: ec<=leads True (150<=200) | appt<=ec True (50<=150) | orders<=appt True (25<=50)`；`current: ec<=leads True (160<=200) | appt<=ec True (40<=160) | orders<=appt True (16<=40)`

**依据与方法**：`week-a.json` 的 `cohort_rule` 声明"各周为当周新登记线索的独立同周漏斗，按客户去重、逐级嵌套"。故须满足 线索 ≥ 有效沟通 ≥ 预约 ≥ 办理。

**结论**：通过（**仅指数值一致性**）。六条不等式 150≤200、50≤150、25≤50、160≤200、40≤160、16≤40 全部成立，两周内各层数量单调不增，数据内部自洽，可直接用同周分子分母计算各段转化率。**但嵌套成立只证明数字上层层不超上层的数值一致性，不证明现实中是同一批客户逐级转化**——材料未给客户标识，客户集合关系无法验证。

**处理**：不需要调整数据；作为后续所有比率计算的结构前提。

## V2｜四项率按原始分子分母复算

**原输出**：
`触达率 prior 150/200 = 3/4 = 75.000000% → current 160/200 = 4/5 = 80.000000%，差 +5.0000 pp | 相对 +6.6667%`
`预约率 prior 50/150 = 1/3 = 33.333333% → current 40/160 = 1/4 = 25.000000%，差 -8.3333 pp | 相对 -25.0000%`
`办理率 prior 25/50 = 1/2 = 50.000000% → current 16/40 = 2/5 = 40.000000%，差 -10.0000 pp | 相对 -20.0000%`
`整体办理率 prior 25/200 = 1/8 = 12.500000% → current 16/200 = 2/25 = 8.000000%，差 -4.5000 pp | 相对 -36.0000%`

**依据与方法**：业务规范定义 触达率=有效沟通/线索、预约率=预约/有效沟通、办理率=办理/预约、整体办理率=办理/线索；百分点差 = 两个率直接相减，相对变化 =（本周−上周）/上周，均用未四舍五入值。

**结论**：通过。另确认：预约率相对变化为 **−25.0000%**，会话中出现的 −24.9% 不成立（差值来自中间四舍五入）。**提出 −24.9% 的是用户；指出并改成 −25.0000% 的是 AI 的解释与纠正，用户未自行修改该数字。**

**处理**：报告正文全部采用上述未四舍五入结果；对外呈现统一保留一位小数并标注 pp 或 %。

## V3｜办理量两级分解与残差校验

**原输出**：
`起点 50预约 x 50% = 25 单`
`预约数改按新值 40 x 上一期50% = 20 单 -> 预约量效应 -5 单`
`办理率改按新值 40 x 40% = 16 单 -> 转化率效应 -4 单`
`合计 -9 单，实际办理 25->16 差 -9 单，残差 0`

**依据与方法**：办理数 = 预约数 × 办理率，按"先换预约数、再换办理率"的顺序逐项代入；残差 = 分解合计 − 实际差额，须为 0。

**结论**：通过（分解闭合，残差 0）。但 −5 单**不是纯预约率效应**：若触达率维持 75.0000%，预约数应为 200×75.0000%×25.0000% = 37.5 人，比实际 40 人少 2.5 人；故 −5 单 = 纯预约率效应 −6.25 单 + 触达改善抵消 +1.25 单。九单减量中约 4.0 单（44.4444%）来自办理率下降，约 5.0 单（55.5556%）来自预约量减少。

**处理**：报告不得把 −5 单直接写成"预约率下降造成 5 单"；须说明内含触达改善的抵消，且不得把 4/9 说成"约一半"。

## V4｜三因素逐项代入的顺序依赖与带符号占比合计

**原输出**（基数 12.500000%、终值 8.000000%、总变 −4.5000 pp，六种顺序均 `守恒 True`）：
`触达→预约→办理: +0.8333 | -3.3333 | -2.0000 | 合计 -4.5000`
`触达→办理→预约: +0.8333 | -2.6667 | -2.6667 | 合计 -4.5000`
`预约→触达→办理: +0.6250 | -3.1250 | -2.0000 | 合计 -4.5000`
`预约→办理→触达: +0.5000 | -3.1250 | -1.8750 | 合计 -4.5000`
`办理→触达→预约: +0.6667 | -2.6667 | -2.5000 | 合计 -4.5000`
`办理→预约→触达: +0.5000 | -2.5000 | -2.5000 | 合计 -4.5000`
带符号占比以 −4.5000 pp 为分母，六种顺序合计均为 `+100.0000%`，首行为 `触达 -18.5185% | 预约 +74.0741% | 办理 +44.4444%`。

**依据与方法**：整体办理率 = 触达率 × 预约率 × 办理率，对三个因子按不同顺序逐项代入并求各步差值；占比 = 单项贡献 / 总变化（带符号），验证合计是否恰为 100%。

**结论**：通过（六种顺序贡献合计均守恒且占比合计 100.0000%）。同时确认：**分项贡献随顺序在区间内移动**（预约 −2.5000～−3.3333 pp，办理 −1.8750～−2.6667 pp，触达 +0.5000～+0.8333 pp），只有总变 −4.5000 pp 与顺序无关。因此"预约段是唯一主因"不成立；可安全断言的是：六种顺序下预约段贡献绝对值均不小于办理段（其中两种顺序两者相等），两段共同拖累。

**处理**：报告中改称"两段共同拖累、预约段略重"，并声明这是逐项代入的数学分解而非因果识别；占比必须注明所依据的代入顺序。**分解只回答"若该因子不变、其余按实际变化，总变化会怎样"，不证明任何业务因果，也不能据此认定责任归属。** 正文不引入对称归因；若需消除顺序影响，仅列可选附录（见 V5）。

## V6｜反事实测算：触达率若维持旧值

**原输出**：`预约数：200 x 75.0% x 25.0% = 75/2（实际 40）-> 触达改善带来 5/2 人`；`对应办理数（按上一期办理率50%）：75/4，实际 16`

**依据与方法**：固定旧触达率 75.0000% 与本周预约率 25.0000%，推算本周预约应为 37.5 人；再按旧办理率 50% 推算办理应为 18.75 单，与实际 16 单相差 −2.75 单。

**结论**：通过。结论方向明确——触达改善本身对办理量是**正贡献**（+2.5 个预约、+1.25 单），说明"有效沟通变多"没有拖累结果，减量发生在有效沟通之后的两段；但触达改善不足以抵补后两段恶化，净减 9 单。

**处理**：写入报告作为"入口与触达不是问题所在"的量化依据；同时明确这是单因素反事实，不是因果实验。

## V7｜口径标注检查（pp 与 % 混用）

**原输出**：回溯稿第二节写 `预约 下降 8.3%`、`办理 下降 10%`；但 8.3333 与 10.0000 是百分点差，按百分比理解应为 `预约 -20.0000%`、`办理 -36.0000%`（见 V2 / 复算第 3 节 `appointments 50 -> 40 Δ -10 -20.0000%`、`orders 25 -> 16 Δ -9 -36.0000%`）。

**依据与方法**：逐条比对回溯稿每个变化值的后缀与 V2 复算结果的单位。原写法"率的差只能用 pp，量的变化只能用 %"说反了一半，现按正确规则核对：**人数的绝对变化用人（或单）；率的绝对差用百分点（pp）；数量与率都可再算相对变化（%）**。本次错误正是把"率的绝对差"标成了 %；而"量只能用 %"的说法不成立——量同样可以算相对变化，如办理 25→16 的 −36.0000%。

**结论**：**不通过**。回溯稿有两处 % 误标，且与其"事实"第 3 条"预约降幅大于办理"直接冲突：按 % 理解办理（−36.0000%）大于预约（−20.0000%）；按 pp 理解办理（−10.0000 pp）也大于预约（−8.3333 pp）。两种口径下该条均不成立。

**处理**：核验稿删除该错误断言，改为"人数口径下预约 −10 人、办理 −9 人；比率口径下预约率 −8.3333 pp、办理率 −10.0000 pp"，并把"下降 8.3%"一律改写为"下降 8.3333 个百分点"。

**结论**：**不通过（首稿越界）**。①"人员岗位或排班变动"不在 `missing_evidence` 四项之内，材料未提，属材料外假设；②"竞品活动或价格调整"同样不在材料中，且业务规范明示无具体金额，不得出现价格数字；③A-N1、A-N2 两条反馈均标注"未统计人数，原因待验证"，只能作线索不能作结论；④`对照试验与动作实施证据`缺失，意味着任何动作效果都无法归因。
